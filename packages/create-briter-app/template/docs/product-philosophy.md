# Product Philosophy

Briter exists to reduce the friction between thinking and publishing.

## Core beliefs

- Writing should feel like sitting down to write, not preparing a deployment.
- The user should own their content as plain Markdown or MDX files in a repo
  they already control.
- Git-backed persistence is a feature, not a compromise.
- A textarea plus live preview is the preferred model. WYSIWYG is explicitly
  not the default.
- Image paste and drag/drop belong in the first version because screenshots are
  often where publishing friction shows up first.
- Publish should not imply rebuilding the world.

## What the app optimizes for

- one person
- one repo
- one writing loop
- boring primitives
- explicit boundaries

## What it does not optimize for yet

- multiple authors
- database-first workflows
- rich-text abstractions
- collaboration
- “content operations” dashboards
